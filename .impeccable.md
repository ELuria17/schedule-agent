# Design Context

## Users

Self-hosted tool for developer-adjacent users: students, hobbyists, and
indie-hacker types who run their own software instead of paying
subscriptions. Not non-technical "general internet." Comfortable copying
a command into Terminal, installing a `.app`, or running Docker. Values
data ownership, code transparency, and a small, fast, honest interface
over polished SaaS marketing.

## Brand Personality

Three words: **crafted, honest, unembellished.**

Emotional goals: competence without swagger. The interface should feel
like it was built by someone who respects the reader's time. No AI
marketing clichés ("seamless", "next-gen", "elevate"). No dashboard-of-
metrics template. No cartoon illustrations. No rainbow gradients.

## Aesthetic Direction

Warm-tinted dark editorial. Think dev-tool-meets-magazine: deep charcoal
canvas, warm off-white text, a single amber/cream accent used sparingly.
Typographic contrast via weight and size, not color. Asymmetric left-
aligned composition. Code samples rendered as code, not as decoration.

**Anti-references** (explicitly avoiding):
- The Vercel/Supabase dashboard look — cyan-on-dark, glowing accents.
- The SaaS-landing template — centered hero, three equal feature cards,
  gradient text, pills and drop-shadows everywhere.
- AI-slop tells: border-left stripes on callouts, gradient text for
  headings, sparklines as decoration, "Elevate your workflow" copy.

## Typography

- Display + UI: **Bricolage Grotesque** (Google Fonts; variable weight
  handles both UI and expressive headings).
- Mono: **JetBrains Mono** for code blocks and keystrokes.

Banned (training-data defaults that create monoculture):
Inter, Roboto, Arial, Open Sans, Fraunces, Newsreader, Playfair,
Cormorant, IBM Plex *, Space *, DM *, Outfit, Plus Jakarta, Instrument
*, Crimson *, Lora, Geist (now overused in AI work).

## Color

OKLCH throughout. Neutrals tinted with ~0.005–0.01 warm hue so surfaces
and text feel subconsciously cohesive with the amber accent.

- Canvas:            `oklch(0.12 0.006 60)`
- Surface (elev. 1): `oklch(0.17 0.008 60)`
- Border:            `oklch(0.26 0.010 60)`
- Text primary:      `oklch(0.96 0.010 80)`
- Text secondary:    `oklch(0.70 0.015 70)`
- Text tertiary:     `oklch(0.50 0.015 70)`
- Accent (amber):    `oklch(0.82 0.14 75)`
- Accent-quiet:      `oklch(0.30 0.06 75)`
- Accent-on-text:    `oklch(0.14 0.025 75)` (for text on amber buttons)

60-30-10: neutrals dominant, secondary text/borders supporting, amber
used for CTAs and small editorial moments only.

## Design Principles

1. **Invisible correctness compounds.** Every detail — line-height,
   transform-origin, easing curve, active-state scale — should be right
   without drawing attention to itself.
2. **Type does the work.** Hierarchy comes from weight and size, not
   color or boxes. No gradient text, ever.
3. **Asymmetry over grids of sameness.** A repeated 3-col feature grid
   is a tell; vary composition to earn attention.
4. **Motion under 250ms, ease-out.** Buttons feel responsive with
   `scale(0.97)` on active. Entry from `scale(0.95) + opacity`, never
   `scale(0)`. Respect `prefers-reduced-motion`.
5. **Honest copy.** If an edge is rough (unsigned builds, API key
   required, iMessage self-sends don't push-notify), say so on the
   landing page, not behind a fine-print link.
